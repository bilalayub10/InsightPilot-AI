Refactor the entire BusinessClassifier into a robust, production-quality, domain-aware classification engine.

Do NOT patch the existing implementation.

Redesign it while preserving the public API:

BusinessClassifier.classify(column_names: list[str]) -> dict

The rest of the application should continue working without any changes.

========================
OBJECTIVES
========================

The classifier should accurately detect the business domain of an uploaded dataset using only its column names.

Current implementation incorrectly classifies datasets because all keywords have equal importance.

Example:

Telecom churn dataset:

CustomerID
Gender
Tenure
PhoneService
InternetService
Contract
MonthlyCharges
TotalCharges
Churn

is currently classified as Sales because "contract" and "account" exist in Sales keywords.

This should instead classify as Telecommunications with high confidence.

========================
REDESIGN REQUIREMENTS
========================

Replace the flat keyword lists with weighted keyword groups.

Each business domain should define:

- high_priority_keywords
- medium_priority_keywords
- low_priority_keywords
- negative_keywords

Scoring:

High priority keyword
+5 points

Medium priority keyword
+3 points

Low priority keyword
+1 point

Negative keyword
-3 points

Generic words like:

customer
account
contract
status
date
id

should NEVER dominate the classification.

Industry-specific words like

revenue
invoice
profit
campaign
diagnosis
patient
churn
tenure
claims
policy
shipment
warehouse
inventory
admission

should carry significantly higher weights.

========================
SCORING
========================

Instead of simple keyword count:

calculate

weighted_score

coverage_score

specificity_score

confidence_score

The classifier should reward

many domain-specific matches

and penalize

only generic matches.

========================
CONFIDENCE
========================

Do not force a business domain.

If confidence is below a configurable threshold (for example 40%)

return

domain = "generic"

instead of guessing.

========================
CODE QUALITY
========================

Maintain the existing architecture.

Keep everything deterministic.

No machine learning.

No external APIs.

No LLMs.

No hardcoded dataset names.

Code should be modular.

Separate

tokenization

scoring

confidence calculation

into small helper methods.

Add clear docstrings.

Add comments explaining the scoring algorithm.

Use modern Python typing.

========================
GOAL
========================

The classifier should feel like the domain detection engine of a professional BI platform rather than a simple keyword matcher.

Accuracy, maintainability, explainability and extensibility are more important than minimizing code length.
